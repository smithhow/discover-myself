# 发现自我 · 关卡动画与结果回看 设计规格

日期: 2026-10-23
状态: 待实现

## 1. 背景与目标

当前版本已接入音效（`audio_service.dart`），但关卡结束时只有 `stage.ogg` 音效和 SnackBar 文字，没有可见动画；同时测评结果虽然写入数据库，却从未被读取，用户再次进入只能重新测评。

本次改动解决两件事：

1. 为关键节点补充轻量动画，优先补齐「有声无画」的关卡完成场景。
2. 提供结果「回看」与「更新（重新测评）」，并持久化历次分数与最近一次的逐题答案。

成功标准：

- 有历史结果的档案再次进入时，可在「查看上次结果」和「重新测评」之间选择。
- 回看可查看最近一次结果及历次分数摘要，回看时不会重复抽奖。
- 关卡完成出现庆祝动画，可跳过，并在约 800ms 后自动继续。
- 系统开启「减少动态效果」时所有新增动画自动降级。
- `flutter test` 全绿，`flutter analyze` 无新增问题。

## 2. 非目标

- 不引入 Lottie / Rive 或任何新的第三方依赖。
- 不保存所有历史答卷，只有最近一次保留逐题答案。
- 不实现云同步、排行榜或跨设备迁移。
- 不改变 PDF 报告的结构和字段。

## 3. 用户流程

### 3.1 选档案

- 档案无历史结果：点击档案直接进入测评，保持现状。
- 档案有历史结果：点击档案弹出底部弹层：
  - 标题：`档案名 · 上次测评 YYYY-MM-DD`
  - 主按钮「查看上次结果」：载入最近一次分数，进入结果页的回看模式。
  - 次按钮「重新测评（更新结果）」：进入测评。
  - 文字入口「历史记录 (N)」：进入历史列表。
  - 点击遮罩关闭弹层，停留在选档案页。

### 3.2 测评完成

- 保存本次分数和逐题答案，作为该档案最新一条结果。
- 清空该档案更早记录的逐题答案。
- 结果列表按档案裁剪到最近 50 条。
- 进入结果页的本次模式。

### 3.3 结果页

- 本次模式：现有内容不变；底部提供「重新测评（更新结果）」「历史记录」「导出 PDF」「抽奖」。
- 回看模式：顶部显示 `回看 · 测评于 YYYY-MM-DD`；隐藏「抽奖」；保留「导出 PDF」「重新测评（更新结果）」「历史记录」。

### 3.4 历史列表

- 按测评时间倒序，每项显示日期、总体评价、各维度分数摘要。
- 点击任意一项进入回看模式，并在回看模式下展示该次测评的时间。

## 4. 数据模型与迁移

### 4.1 表结构

数据库版本从 1 升到 2。

`assessments` 表新增字段：

```sql
answers_json TEXT
```

- `onCreate` 直接创建含 `answers_json` 的表。
- `onUpgrade` 从 1 到 2 执行 `ALTER TABLE assessments ADD COLUMN answers_json TEXT`。
- `Database.open` 的测试工厂分支和生产加密分支都使用版本 2。

### 4.2 新模型

新增 `AssessmentRecord`：

```dart
class AssessmentRecord {
  final int id;
  final DateTime finishedAt;
  final Map<String, double> scores;
  final Map<String, int>? answers; // 仅最近一次可能非空
}
```

### 4.3 数据库方法

- `latestResult(int profileId)`: 返回最近一条记录（含答案），无记录返回 `null`。
- `resultHistory(int profileId)`: 返回该档案全部记录，按 `finished_at DESC`。
- `pruneResults(int profileId, {int keep = 50})`: 删除超出 `keep` 的最旧记录。
- `insertResult(...)`：增加可选 `answers` 参数，写入 `answers_json`。

### 4.4 写入事务

提交结果时在单个事务内完成：

1. 插入本次结果（分数、答案、时间）。
2. 将该档案更早记录的 `answers_json` 置空。
3. 裁剪到最近 50 条。

### 4.5 读取

- `AppCoordinator` 增加 `latestResult()`、`resultHistory()`，均针对当前 `activeProfile`。
- 回看时用历史分数重新计算成长建议，逻辑与本次结果一致。
- 分数 JSON 无法解析的记录跳过；若最近一条无效则视为无历史。
- 加密与离线约束不变，不新增存储位置。

## 5. 动画设计

### 5.1 关卡完成庆祝

- 在 `AssessmentScreen` 内使用 `Stack` 叠加一层非路由遮罩，避免弹窗与 widget 测试冲突。
- 内容：关卡名（如「第 2 关 · 认知能力」）+ 徽章缩放进入 + 约 12 个光环粒子。
- 粒子使用 `CustomPainter` 绘制，不引入新资源。
- 时序：与 `stage.ogg` 同时出现，约 800ms 后自动继续；点击可立即跳过。
- 遮罩显示期间拦截答题事件，防止连点跳关。

### 5.2 进入结果页

- 结果页根节点 300ms 淡入并上移 16dp。
- `ResultScreen` 改为 `StatefulWidget`，用一个 `AnimationController` 统一驱动入场与分数条。
- 分数条按索引 80ms 错峰生长，替代当前同时开始的 600ms 动画。

### 5.3 抽奖

- 保留现有 1.1s 开奖和弹性缩放。
- 开奖后增加约 20 个彩带粒子，2s 淡出，使用 `CustomPainter` 与现有动画控制器实现。

### 5.4 降级

- `MediaQuery.disableAnimations` 为真时：跳过庆祝层、彩带和错峰，直接淡入或立即显示，时长归零。
- 不新增任何依赖或资源包体积。

## 6. 错误处理

- 读取历史失败：提示「读取历史失败」，停留在选档案页，不影响重新测评。
- 分数 JSON 损坏：跳过该条记录；最近一条无效则按无历史处理。
- 数据库迁移失败：沿用现有解锁失败处理，密钥与数据保持清空状态。
- 提交事务失败：提示「提交失败，请重试」，不留下部分写入。

## 7. 测试

### 7.1 单元与数据库

- `database_test`：1→2 迁移、`latestResult` 顺序、只有最新记录保留答案、超过 50 条裁剪。
- `app_coordinator_test`：`latestResult` / `resultHistory`、提交时写入答案。
- `summary_test`：历史分数重建总体评价与建议（复用现有逻辑）。

### 7.2 Widget

- 有历史 → 选档案出现二选一弹层；无历史 → 直接进入测评。
- 「查看上次结果」进入回看模式，抽奖按钮隐藏。
- 「重新测评」进入测评并完成新一轮。
- 关卡庆祝层出现、可跳过、自动继续。
- `disableAnimations` 下不出现庆祝层和彩带。

### 7.3 回归

- `flutter test` 全部通过。
- `flutter analyze` 无新增问题。

## 8. 关键决策

- 采用「入口二选一 + 结果页按钮」路线，改动集中且贴合使用习惯。
- 历次结果只存分数与时间，上限 50 条；逐题答案只保留最近一次。
- 回看模式隐藏抽奖，避免重复领取。
- 动画只用 Flutter 内置能力，不引入 Lottie / Rive。
- 「更新」统一命名为「重新测评（更新结果）」。
